\section{Findings}
\begin{description}[style=nextline,leftmargin=0.9cm,nosep]
  \item[F-01 --- Medium, Design ruling required] For a legacy 007 assessment with \texttt{verified=true}, adding an \emph{active unverified} \texttt{exam} milestone removes its Calendar event with no replacement (unverified is not eligible). \texttt{MilestoneForm} gives no warning; only Overview later shows ``Tentative · not on Calendar''. Conflicts with DESIGN \S5.1 (``do not lose its existing Calendar visibility''). Tests cover only source-verified replacement. Cause: \texttt{globalCalendarService.ts} adds the assessment to \texttt{examAssessmentIds} \emph{before} \texttt{isCalendarEligible}. Repro: verified legacy assessment $\to$ \texttt{setMilestone(\{kind:'exam', datePrecision:'date-only', localDate, verificationStatus:'unverified'\})} $\to$ calendar query lacks \texttt{calendar-assessment:<id>}. Cancelling that milestone restores the legacy event [SRC]. Options for Design: (a) unverified milestone does not hide the legacy event until confirmed; (b) keep behaviour but warn at save and label in Exams; (c) accept as explicit user correction.
  \item[F-02 --- Medium, disclosure] The developer table titled ``Complete CI history (nothing omitted)'' omits run 45047256878 (\sha{bcdb26d}, smoke 4 failures) and 45045784496 (\sha{d131025}, Node 22 failure). The following commit \sha{ed1c409} made the route check case-insensitive and moved \texttt{/favicon.ico} 404 to ``reported, not failed''. QA verified the filter is narrow (\texttt{source==='network' \&\& pathname==='/favicon.ico'}) and the change is reasonable, but it is an assertion relaxation after a failure and should be disclosed. The Design Window authorization also does not record these runs.
  \item[F-03 --- Low, accessibility, pre-existing] Focus sits on \texttt{body} for 5--28\,ms after Escape (15/15), because the shared, unchanged \texttt{InspectorShell} restores focus in a passive \texttt{useEffect} cleanup after the aside is removed. Consistent with the old single-read smoke failures being a timing race. Not a 009 regression; final focus always correct; screen-reader impact \NV. Possible future change (Design decision): restore before close or use a layout-effect cleanup.
  \item[F-04 --- Low] Overview \texttt{summary()} filters ``upcoming'' only by milestone date; a legacy verified exam without milestone stays ``upcoming'' even when its date has passed.
  \item[F-05 --- Low, UX] Paper Inspector shows \texttt{available-here/managed} as ``Available'' while ``Open original'' is disabled with no explanation (consistent with the global \texttt{openOriginal} contract, but confusing).
  \item[F-06 --- Low, cosmetic] Lowercase zone \texttt{europe/berlin} accepted and stored non-canonically (conversion correct); legal legacy names \texttt{GMT}, \texttt{EST5EDT} rejected; Pacific/Apia skipped day reported as ``daylight-saving gap''; year 1899 reported as ``Not a real calendar day''.
  \item[F-07 --- Low, reporting] Smoke \texttt{"checks":30} is \texttt{evidence.length} (log rows), not assertions; ``30/30 checks'' is a mislabel (\texttt{failures:0} is real) and is not 30 product acceptances.
  \item[F-08 --- Low, coverage] Real-browser smoke does not exercise Tab trap, card$\to$Escape focus, past paper / practice creation, permission or missing Resource states, DST fold UI choice, registration or sitting forms (\texttt{Tab} key defined but unused).
  \item[F-09 --- Info] 007 free-text \texttt{registrationStatus} is preserved but not displayed; no code in \texttt{src} writes it, so the risk is theoretical.
\end{description}
