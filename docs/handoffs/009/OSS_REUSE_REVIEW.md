### Scoring and selection

- **Most robust semantics for frozen D2**: **Temporal polyfill** is the preferred *optional* date-engine candidate because the business contract must keep `PlainDate` separate from an exact zoned instant and reject DST gaps/overlaps rather than silently normalize.
- **Smallest footprint fallback**: `@date-fns/tz` with a dedicated strict validator for exact local times, if the selected Temporal package creates an unacceptable bundle, engine, licensing or runtime issue. This is **not preauthorization to install both**; a substitution must be reported and approved at the separate execution gate.
- **Lowest API onboarding cost**: Luxon; not recommended as the first choice because the domain's date precision model is better isolated with Temporal.
- **No date dependency is required for data-only milestone persistence**: `YYYY-MM-DD` strings may remain strings; use selected library only for validated exact date+zone → instant conversion and safe formatting. Internal storage must be independent of vendor types.
- **Selected reuse approach**: Allow **at most one** justified timezone library in Module 009, preferably `@js-temporal/polyfill`; do not add any other UI/calendar/table/date frameworks without a new Design Window scope review. The code executor must capture exact installed package version/lockfile diff, license, `npm run build` output, browser compatibility and DST test cases; if compatibility fails, **STOP** for reapproval rather than silently changing candidates or adding multiple dependencies.
- **Important provenance**: The date-fns star count is **for the whole monorepo**, not the `@date-fns/tz` package. Repository activity is not proof that every package was recently modified. Last commit dates are from GitHub's commit API; do not confuse `updated_at` or last push with source commit dates.
- **All three are reference candidates, not copied source**: do not vendor code, copy LICENSE-protected source into the application or install optional dependencies before a user-initiated, expressly authorized development window. Compliance includes attribution/third-party notices if a package is actually used.
