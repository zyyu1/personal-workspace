## 2. Real merged 007 interface map (verified from main)

| 008 requirement | Current accepted 007 implementation | Required safe 008 adaptation |
| --- | --- | --- |
| CourseOffering identity and Materials | `src/features/study/types.ts`: `Course`, `CourseOffering`, `CourseMaterialSource`, `CourseMaterialEntry`, `CourseSection`, `CourseOfferingView` | Reuse these ID types and `CourseOfferingView`; all 008 Units/Sets/Items/Attempts must be scoped to `offeringId`, not conflated with `courseId`; material classification `CourseSection` is **not** a learning-outline Unit. |
| Canonical 007 repository | `StudyCourseService` in `src/features/study/services/studyCourseService.ts` uses `createVersionedRepository<StudyState>({domain:'study-courses',schemaVersion:1,seedVersion:1,...})`; `StudyState` has `progress`, `assessments`, `sources`, `entries`, `sections` | Safely add typed learning definitions, exercise/attempt records and progress operations via shared persistence; prefer one versioned canonical Study domain. If schema changes, upgrade with an **explicit v1 → v2 migration/back-up** using `migrate`; never discard or reinitialize existing accepted 007 IndexedDB data. |
| 007 resource-level study marks | `CourseStudyProgress`: `{id,offeringId,resourceId?,sectionId?,state:'not-started'|'studying'|'studied'|'reviewed',updatedAt,noteId?}`; `StudyCourseService.markProgress(offeringId,resourceId,state)` | Preserve **all existing** per-resource states, IDs, timestamps and 007 UI behavior. Implement typed target discriminators for resource / learning-unit / exercise-item in **one** canonical progress source; do not add a parallel 008 progress LocalStorage key. Account for the legacy `reviewed` status separately from the new manual Unit mastery axis. |
| Existing resource identity/link | `GlobalResourceService` owns one `WorkspaceResource`, `ResourceLink`, availability/permission and openOriginal; `ResourceEntityType` already includes `course-offering` and `task` but **not** learning-unit / exercise-set / exercise-item | Link canonical Resource IDs without copying bytes; use a minimal typed relation safely scoped by offering, extending ResourceLink entity types only as needed; no leakage to other Offerings or automatic deletion on missing material. |
| Existing tasks/calendar | `GlobalTaskService.create({projectId,area:'study',title,stage,taskType,...})`; `projectId` is actual offering ID; `GlobalCalendarService.query({projectId,...})` and shared Task/PlannedSession | Create exactly one Task per explicit action; use existing task ownership and date/session APIs; due date, review date, Session and verified CourseAssessment remain distinct. No second Task service/store or inferred deadlines. |
| Global time | `TimeEntryService.list(offeringId)` and `TimerSessionService`; `TimeEntry` has canonical `durationSeconds` (else minutes) and session identity | Do not write TimeEntries merely for an ExerciseAttempt or automatic study event. Only the Global Timer Finish creates actual time, with existing idempotence. Preserve sub-minute precision and correct filtering. |
| Resume | `WorkspaceResumeService.record/resolveLatest(offeringId,'study')`; current entity enum is `paper|task|experiment|project|resource|section`; 007 safely validates resource / study section | Extend **minimally** for `learning-unit` and `exercise-item` with actual existence/offering checks; query-driven `?unit=` and `?exercise=` deep links, no arbitrary route strings or cross-area fallback. Continue never starts timer. |
| UI routes / tabs | `src/App.tsx` route `/study/courses/:courseOfferingId/:section`; current StudyCoursePage maps **any non-Materials section to Overview**. `CourseWorkspace` owns `overview|materials`, `StudyTabs` shows Exercises as Future and no Progress tab. | Add explicit `progress`/`exercises` branch, functional tabs, shared Course header and `InspectorShell`; preserve 007 Overview/Materials, disabled Exam/Lab/Note tabs and Research/global routes. |
| 007 Overview progress card | Current `CourseWorkspace` calculates a simple percentage of resource-level `data.progress` | Replace only that projected summary with **derived 008 `CourseProgressQuery`**: studied `x/y`, solved `a/b`, review count, unknown when unconfigured. Never duplicate a mutable course-progress counter; 007 resource-level mark continues to work. |
| Persistence guarantees | `src/data/persistence/repository.ts` serializes mutations, backs up stored envelope before a registered migration, fails on unsupported future schema, exposes `MutationResult`. `RepositoryDomain` includes `study-courses`. | Reuse serialization, backup/migrate, validation and error handling. Cross-domain ResourceLink/Study writes are **not atomic**; do not claim success if only one succeeds. Document recovery/reconciliation tests. |

These are **known extension points consistent with the frozen 008 design**, not newly approved alterations to the design. If implementation encounters an actual incompatible repository version, data-loss scenario, unresolvable cross-repository integrity conflict or a required design-semantic change, **STOP** and return the exact proposed interface/design change to Design Window before continuing.
